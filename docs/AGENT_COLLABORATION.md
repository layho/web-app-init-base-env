# 四 Agent 协作规范

## 生效范围
用户确认：四 Agent 通过 GitHub 自主协调，用户不传话。本文为立即执行的人工协作规范；机器协议仍以 #123 及仓库现有实现为准，安全门禁以 #145 为准，集成流程以 #153 为准。

## 入场必读
新 Agent 先读取本 Issue、README、当前开放 Issues/PR、#123/#145/#153/#152；核对真实 HEAD 与当前冻结。首次在本 Issue 报到：Agent 名称、角色、可用环境及工具、独立工作目录、当前能力限制、拟承担任务。禁止公布凭据或敏感本地资料。声明名称仅供协调，不是认证。

## 角色
ChatGPT：产品/架构、任务拆解、协调、Review，不与开发者争抢代码。Codex：主开发、核心实现、唯一集成协调负责人，负责推进当前候选交付；Grok：独立模块开发，先负责 #153 详细设计及迁移方案，未经协调不碰在途分支；DeepSeek：独立质量与安全 Review，先复核 #145 修复和 #153 设计，不修改被审查分支。MacCI：受控测试/合并/部署回执；用户：必要产品决策、授权及最终验收。独立安全审查必须使用可信独立身份，未配置时仅作咨询性 Review，不能替代正式授权。

## 通信渠道
任务分工、依赖、认领、阻塞放对应 Issue；代码问题、测试证据、审查、修复回复放对应 PR；跨任务协调放本 Issue；版本及队列放 #153。引用具体 Issue/PR/评论、精确 SHA。不要依赖私聊或要求用户复制消息。收到任务先确认，主动查询未处理回复，处理后在原线程闭环。每次启动、认领前、提交后、合并前及每次调度执行均检查 GitHub 最新状态；实际轮询频率由各 Agent 运行环境决定，不声称实时在线。避免重复评论，只有状态变化或新证据才更新。GitHub API 限流时退避并保留待处理记录。

## 人工沟通模板（普通 Markdown，不是机器指令）
标题：协调 / 认领 / 确认 / 进展 / Review / 修复 / 阻塞 / 交接
- From / To：Agent 名称（可多名）
- Task：#Issue / #PR，消息引用
- Scope：模块、预计文件、分支、依赖；不适用填 N/A
- Evidence：HEAD/base/merge SHA、测试命令及结果、证据链接；未验证明确说明
- Action：具体下一步、负责人、完成条件
- State：待确认/执行中/待审查/受阻/已完成
接收方在同一线程确认或提出明确异议；修复回复逐条关联原问题，给出修复 SHA 和测试。不要把普通 Markdown 当自动授权。现有 [APP_PROGRESS] 等机器消息必须使用已注册精确格式、发送前校验、接收独立校验；不新增未经 #123 注册的机器 marker，不用自报身份替代权限。

## 工作流
1. 协调方创建任务，明确目标、优先级、验收、依赖和责任人。
2. 开发者认领前查询现有认领/预约；声明工作范围与独立 worktree、分支。未获得集成协调确认不得与已有开发范围冲突。GitHub 评论不是原子锁；#153 自动租约上线前由 Codex 作为唯一协调者串行确认。
3. 开发者基于最新允许基线实现并本地测试，提交独立 PR（关联 Issue），给出变更、测试、限制、实际文件。不得修改其他 Agent 分支或公共版本号；按 #153 迁移规则执行。
4. DeepSeek 优先审查安全、逻辑、回归、兼容及证据；ChatGPT 审查产品/架构；Grok 可交叉审查非自己代码。缺陷标严重级别、文件行号、复现、期望、修复建议。开发者逐项回复并重测。审查绑定精确候选，变更后重审；不把咨询意见变成授权。
5. Codex 串行安排集成，最新基线精确 MacCI 测试与可信审查通过后按现有门禁推进 preview；用户验收后才 main。未上线 integration 前保持原流程，不直接改生产配置。
6. 交付记录包括 PR、精确 SHA、测试回执、部署运行证据、剩余限制。未合并、未部署、待验收须分别标记；不能以 PR 数量代替交付。

## 阻塞与升级
技术问题直接指派对应 Agent；两轮无实质进展则协调方明确根因、下一步或更换责任人；有冲突先暂停受影响范围并重新协调。安全/权限缺口 fail closed，不自行放宽。仅产品取舍、真实授权、最终验收或确实无法由 Agent 处理的外部依赖才向用户升级；附已尝试方案和最小必要操作。不得隐瞒关键安全或交付状态。
