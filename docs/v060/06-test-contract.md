# V0.6.0 测试契约与隔离夹具

执行者：Grok。正式测试走 MacCI 的精确 head、base、merge 回执，不使用 GitHub Actions，不在生产做故障注入，不索取秘密。

W00 已落地的只有本地契约夹具：`tests/test_v060_w00_contract.py` 读取 `tests/fixtures/v060/w00/`。它执行草案里的状态转换、租约代次、幂等顺序、候选编码和分流水位。它不断言生产行为已经改变，也不把草案当成已经冻结。

## 必须覆盖的路径

正常路径：反馈同步、领取、开发回执、精确测试、预授权允许时的 preview、部署、用户验收、main、任务收尾。每段都要有同一个 task_id 下的 run_id、执行身份和证据引用。

失败路径：非法阶段跳转、过期租约、候选四元组变化、冻结、策略拒绝、缺执行器、重复幂等键但载荷不同、生产者序号缺口、部署中断、回滚后旧健康失败、平台不支持。

精确候选：head、base、merge、tree 任一不一致都不得复用测试、验收或部署成功。`app/candidate_evidence.py` 已有局部判断，W11 之前要用新的四元组样例重新核对，不把旧单测结果当成 V0.6.0 实机通过。

## 夹具规则

- 只使用占位 SHA、`test-proof://` 和 `idem-w00-*` 键。
- 断言失败信息不得打印环境变量。
- 夹具目录不放 `.env`、token 或数据库连接串。
- `implemented` 必须保持 false，直到对应工作包真正注册路由并通过评审。那时候升 schema 或改夹具状态，不能假装 W00 已经启用。

## 证据缺口与补证责任

| 缺口 | 为什么本轮没有 | 谁补 |
| --- | --- | --- |
| MacCI、调度器和 HostOps 的运行 SHA、安装回执、dispatch 开关 | 执行者没有宿主登录 | 用户或基础环境验收提供只读摘要。ChatGPT 协调最小必要操作。Grok 收到摘要后再分类 |
| `logs/pr-active.json` 与反馈缓存是否在 #202 之后回退 | 缓存不在这个工作区 | 同上，只读拷贝或 HostOps 安全摘要。不要粘贴原始日志 |
| classic branch protection | 本轮 GET 为 403 | 具备管理读取权的只读核对，按身份矩阵的五步。Grok 记录结果，不改规则 |
| 组织级 ruleset 和 bypass | 仓库 rulesets 空列表不能回答 | 同上 |
| 外部执行器是否真正消费任务 | 源码没有这条调用，本机也不可见 | 执行器所属方给出 run_id 回执。没有回执就保持 UNKNOWN_EXECUTOR |
| Panel #13 的当前 PR 状态和前端失败细节 | 本轮没有重读该仓库 PR | W08/W06 开始前由协调者重取公开 PR 状态。原始日志不进入 Issue |
| Linux 机器 | 没有该环境 | W09，且只能在隔离机器。W00 不申请 |
| 生产数据库结构或 ACL | 禁止 | 不补。需要时走单独的人工变更，不由测试夹具连接 |

补证材料只含状态、时间、SHA、规则编号和脱敏原因。发现材料里有秘密时停止引用，不转贴。
