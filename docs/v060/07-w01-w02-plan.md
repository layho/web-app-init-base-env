## 并行子任务

W01 与 W02 的第一轮不修改同一文件，也不修改 `app/main.py`、`deploy/macmini/manage.sh` 或凭据加载。

| 子任务 | 包 | 路径 | 验收 |
| --- | --- | --- | --- |
| W01-A 校验器 | W01 | 新目录，只读 `tests/fixtures/v060/w00/contract.json` | 合法转换通过；终态出边、缺幂等键、错误 schema_version 失败。不导入 `app.db`，不打开网络 |
| W01-B 先落盘 | W01 | `deploy/macci/runner.py` | 现有 `deploy/macci/test_runner.py` 仍通过。新增夹具在本地报告写入后、远端 status 之前终止，重启后同一 run_id 仍可投递，且不会写成第二个成功 status |
| W01-C 轮次校验 | W01 | `app/feedback_progress.py` | 旧的合法 APP_PROGRESS 仍可解析。带新 run_id 的非法回退不改变当前轮次。不把 ChatGPT 加入信任枚举，不扩大 author_association |
| W01-D 旧事件读取 | W01 | `app/operations.py` | 旧的三列和四列样例仍解析。新字段缺失时标 legacy_unscoped。读失败与空文件是两个结果 |
| W02-A 策略评估 | W02 | 新目录 | 矩阵外的角色和操作默认拒绝。`policy_evaluate_deny` 样例返回 POLICY_DENIED 且不写存储。`authorize_request()` 的现有测试不变 |
| W02-B 测试身份 | W02 | 新夹具 | MacCI、发布器和用户验收三份证明不能互相代替。过期和四元组不符都失败。夹具不含真实 token |
| W02-C 验收绑定 | W02 | 先只做纯函数和夹具，不改 `release_acceptance.py` | 候选 proof 调用发布评估被拒绝。改生产验收文件需要另一次授权和 S-auth 窗口 |
| W02-D 分支保护记录 | W02 | 只追加证据文档 | 重复身份矩阵的只读五步。403 和空 ruleset 仍写未证实。diff 里没有规则变更 |
| W02-E 凭据入口说明 | W02 | 文档，列出已有环境变量名 | 说明多变量回退和“一次配置、分身份使用”的差距。测试不读取这些变量的值，不改 `load_env` |

W01-A、W01-B、W01-C、W01-D 彼此路径不同，可以并行。W02 的五个子任务也可以并行。任一侧若要改 S-merge 或 S-auth 里的文件，并行停止，先预约。

W01 完成的含义：上述四项验收通过，新路由未注册，默认仍读旧事件。W02 完成的含义：评估器和夹具通过，生产认证行为的 diff 为空，除非另有用户授权把 S-auth 打开。
