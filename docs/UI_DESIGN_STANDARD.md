# 基座 UI 设计与交付规范

用户确认 2026-11-25 开发任务看板设计作为今后页面质量基线。先完成页面设计和主要交互确认，再开发。使用 React + Ant Design 现有组件与统一蓝灰企业 SaaS 风格，清晰层级、留白、紧凑信息、轻量边框、状态色用于语义而非装饰。

- 页面必须利用可用宽度；内容区响应式，不用全局固定最大宽度限制看板。桌面多列、平板自适应、窄屏单列；不得产生整页横向溢出。复杂表格允许局部滚动。
- 看板默认按真实任务阶段分组，阻塞独立突出；历史默认隐藏，可筛选。任务数量来自真实数据，缺失状态显示未记录，禁止虚构成功或测试统计。
- 统计卡可筛选、搜索和负责人/优先级过滤可组合，完整详情在抽屉；长 PR 关联摘要显示，详情保留全部。
- 已有功能和安全门禁不得因 UI 改造删除或弱化；禁止拖拽伪造交付状态，禁止提供无后端支持的按钮。
- 验收至少检查宽屏 1920/1440、平板 768、手机 390，键盘操作、长标题、空数据、同步失败、多个 PR、测试失败、历史任务、所有旧操作。真实浏览器验证与 MacCI 构建通过后才交付。
- 新应用继承共享基座设计和响应式外壳，业务页面先设计后实现。
