# Security and trust boundaries
Default deny. Public Base application is untrusted for host execution authority. Separate requester and agent credentials, scoped by host and operation; no agent secrets in frontend. Agent outbound TLS with server authentication, signed job envelope binding host, actor, operation, canonical params digest, expiry, nonce, policy version; replay protection persisted locally. Root-owned local policy is outside remotely writable paths; agent cannot amend it. No shell=true, eval, arbitrary executable, path, environment, URL, sudo or remote script payload. Fixed argv, sanitized environment, fixed cwd, output caps, timeout, process group cleanup. Do not read .env, keychain, tokens, SSH keys, database secrets; logs allowlisted and redacted before leaving host. No arbitrary shell even through UI or MCP in V1. L1 read-only, L2 specifically preauthorized safe service actions, L3 exact released artifact digest and scoped approval, L4 unsupported remotely. Existing MacCI trusted installer is a separate privilege boundary; do not weaken it. Broker design needed before HostOps may control layho LaunchAgents; separate account cannot assume access to GUI domain. Audit tamper resistance is a requirement, not a claim. Threat tests: unauthorized request, replay, altered params, lease race, path traversal/symlink, command injection, secret leakage, stale digest, policy changes, compromised gateway, failed upgrade.
