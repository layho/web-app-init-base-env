# MacCI main publisher

Separate trusted host LaunchAgent; every 60 seconds. Only processes owner-originated, open [BASE-ACCEPTANCE SHA] issues backed by the local private webpage receipt in ~/web-app-init-base-env-preview/logs/release-acceptance. The current web API still performs the explicit human confirmation, session/CSRF checks, deployed SHA verification and creates the receipt. No automatic acceptance.

Verifies the exact candidate, expected main baseline, preview ancestry, merged preview PR, latest owner MacCI success with matching parent SHAs and tree, and version file. Never publishes current preview merely because it is newer. Git non-force push uses existing SSH; respects GitHub protection, no new all-repository Contents-write token. On actual main success (or recovery after successful push), acknowledge and close the issue using the existing Issues-write token. If acknowledgement fails, main is not pushed again. If current main has diverged, stop rather than force. Raw secrets and issue content are not logged. Keep GitHub branch protection in place; host SSH credentials themselves are not inherently branch scoped.

After CI passes and code review, install once via SSH from the approved PR branch checkout: bash deploy/macci/install-main-publish.sh. This does not overwrite the test or preview services. The service will process existing genuine local acceptance receipts, so do not install before you authorize this behavior. View ~/.local/share/macmini-pr-tests/main-publish.log; launchctl print gui/$(id -u)/com.layho.macci-main-publish. To trigger immediately: launchctl kickstart gui/$(id -u)/com.layho.macci-main-publish. No -k. To check without publishing: python3 ~/.local/share/macmini-pr-tests/publish_main.py --dry-run. No self-update from unreviewed code. ChatGPT scheduled task stops main publishing only after local service is installed and actual receipt-processing evidence is observed; no duplicate push.
